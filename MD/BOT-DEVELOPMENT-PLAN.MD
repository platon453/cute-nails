# План разработки Telegram-бота для записи на ноготочки 

## Стек технологий 
- **Язык**: Python 3.11+
- **Фреймворк**: aiogram 3.x (самый современный и быстрый для Telegram)
- **База данных**: PostgreSQL (работает в Docker для удобства)
- **ORM**: SQLAlchemy 2.0 (асинхронный режим) + Alembic (для миграций БД)
- **Управление состоянием**: FSM (Finite State Machine) из aiogram
- **Интерфейс админа**: Inline Keyboards (встроенные кнопки прямо в чате)
- **Инфраструктура**: Docker & Docker Compose (для запуска бота и БД одной командой)
- **Зависимости**: Все пакеты будут фиксироваться в `requirements.txt` для удобства разработки и деплоя.

## Основной функционал
### Для клиента (пользователя):
1. Команда `/start` приветствует пользователя.
2. Бот показывает красивые Inline-кнопки с доступными датами, а затем со свободным временем.
3. Клиент выбирает время, бот запрашивает **Имя** и **Номер телефона** (через кнопку "Поделиться контактом").
4. Заявка отправляется админу на подтверждение (у клиента статус "Ожидание").
5. После подтверждения админом, клиент получает красивое сообщение об успешной записи.

### Для админа (подруги):
1. Права админа выдаются через конфигурационный файл (`.env`) и проверяются в Middleware.
2. Админ может зайти в специальное меню (например, по команде `/admin`).
3. **Управление слотами**: Админ добавляет свободные даты и время через удобный интерфейс с кнопками.
4. **Подтверждение записи**: При новой заявке админу приходит сообщение с данными клиента и кнопками `✅ Подтвердить` / `❌ Отклонить`.

## Поэтапный план разработки

### Этап 1: Инициализация проекта и База Данных 
- Настройка структуры проекта.
- Создание `docker-compose.yml` для PostgreSQL.
- Настройка SQLAlchemy 2.0 и Alembic.
- Создание моделей БД: `User` (клиенты), `Slot` (свободные окна), `Booking` (записи).

### Этап 2: Базовый бот и Middlewares 🤖
- Настройка aiogram 3.x, создание основного файла запуска.
- Написание Middleware для автоматического прокидывания сессии БД.
- Написание Middleware для проверки прав админа (по ID из `.env`).

### Этап 3: Админка (Управление расписанием) 📅
- Создание админ-панели (Inline-клавиатуры).
- FSM-стейты для добавления новых дат и временных слотов.
- Возможность просмотра и удаления свободных слотов.

### Этап 4: Клиентская часть (Процесс записи) 📝
- Команда `/start` и вывод доступных дат.
- Выбор времени клиентом.
- Запрос имени и телефона (сохранение в БД).
- Отправка уведомления админу с кнопками подтверждения.

### Этап 5: Финализация бронирования ✅
- Обработка нажатий админа (Подтвердить/Отклонить).
- Изменение статуса слота в базе данных.
- Отправка финального уведомления клиенту.
